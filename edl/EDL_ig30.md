## 音楽

アコースティックギターかピアノが主体の、ミニマルなインスト（ボーカルなし）。BPMは80〜90。明るすぎない長調で、海辺の午後の温度感にする。EDMのドロップ、派手なビルドアップ、効果音の連打は使わない。

【音源】商用利用できるライセンスの曲を使い、編集ソフト上でカットに合わせて編集する。Instagramの楽曲ライブラリは使わない。ライブラリの曲はカットに合わせて編集できないので、下の拍合わせと「0.00〜1.50はBGMなし」の設計が成り立たないため。どうしてもライブラリを使う場合は拍合わせを諦め、現地音だけのミックスを−14 LUFS近くまで上げて書き出し、投稿時に曲を付ける。

【構成】0.00〜1.50はBGMなし（波音だけ）→ 1.50のカット頭で最初の音 → 4.00（入店）に拍を合わせ、席までは軽いリズム → 13.40〜16.60（パスタのスロー）は音数を減らして持続音中心 → 16.60（ケーキ）でリズムが戻る → 24.70のEnd Cardで最後のフレーズ → 29.00から消え始め、29.70で消える（最後の0.3秒は波音だけ）。カット位置はEDLのまま動かさず、BGMの側を切ってつなぎ、4.00・13.40・24.70に拍を合わせる。

【音量の目標】実測のラウドネスは、9672（18.5〜20秒）−40.7、9658 −39.7、9660 −43.2、9661 −40.6 LUFS。店内の同期音は−26〜−33 LUFS。
① 冒頭の波（9672＋9658）：ノイズ除去のあと約+20dB。短時間ラウドネスで−18〜−20 LUFS。
② 本編のBGM：約−16 LUFS。
③ 現地音：BGMの6〜8dB下に置く。ただし0.00〜1.50、22.30で波が開く瞬間、最後の0.3秒は波音が主役。
④ 最後にリミッターで、全体を−14 LUFS（integrated）、トゥルーピーク−1dBTPに合わせる。
+20dBでノイズが目立つ場合は、0.00からBGMの弱いパッドだけを薄く敷く。

## 色（HDR→SDR）

全クリップがHLG（BT.2020）の10bit HDRなので、同じ手順でRec.709のSDRへ変換する。FFmpegのzscale → tonemap=hable（desat=0）→ bt709 で一括処理し、元の解像度（3840×2160／2160×3840）・元のfps（9646は120fpsのまま）で、10bitのProRes 422 HQの中間ファイルにする（capcut_tasksの0。サイネージのEDLと同じ仕様）。カット2の中間ファイルも、同じトーンマップ・同じ10bit（ProRes 422 HQ）で作る。CapCutの自動HDR変換には任せない。8bitになるのは最後の書き出しだけにする（カット2は画面の上半分がなめらかな青空なので、途中で8bitに落とすと、グレーディングとInstagramの再圧縮で縞が出やすい）。変換後は次のように整える。
・海：青〜ターコイズを自然に見せ、彩度は少しだけ上げる。9672と9668のターコイズが緑に転ばないよう、色相を固定する。9661と9636の淡い空は、青を少しだけ戻す。海のカット（9672／9665／9636／9668／9661）どうしで、青の色相と明るさをそろえる。
・カット1（9672）：白波のハイライトと、浅瀬のターコイズのコントラストをほんの少しだけ上げる（HOOKの強さを出す。やりすぎない）。
・カット2（9665）：快晴で空の青が濃いので、空の彩度は足さない。外洋の濃い青と水路のエメラルドは、緑に寄せずに実景どおり残す。白い砂州のハイライトは飛ばさず、砂の粒が見える程度に保つ（10bitの中間ファイルでは、砂州の99パーセンタイルが白の上限940に対して約870で余裕はあるが、砂州は上げない）。
　水路の見え方の補強：中間ファイルをひとつ上のトラックに複製し、画面の下約22%に、上端を大きくぼかした線形マスクをかける。複製の方だけ、HSLで青緑（シアン）の輝度を+0.2〜0.3段相当、彩度を+5%前後だけ上げる。色相は動かさず、緑に寄せない。露出で帯全体を上げると、同じ帯にある砂州の下の縁が白飛びの手前まで明るくなる（試算で、その帯の明るさの99パーセンタイルが228→243/255）ので使わない。青緑だけに絞った試算では、砂州は変わらず、水路の平均がRGB 75/126/142 → 77/136/153になる。目的は、キャプションの下の暗いグラデーションを通しても、水路がエメラルドとして見えるようにすること。やりすぎない。
・カット12（9661）のEnd Card：画面の上約60%に、下へ行くほど効きが弱まるマスクをかけ、空を−0.5〜−0.7段落とす。効きは水平線の少し上で0にする。自然な青を戻す範囲に収め、灰色っぽい空や不自然な濃紺にはしない。これは空の露出の調整で、文字の装飾（縁取りやグラデーション）ではない。調整後に、白い文字がスマホの実機で読めるかを確認する。
・Teal & Orangeは禁止。影に青緑を足したり、暖色を橙に寄せたりしない。
・店内（9673／9643、撮影後のE7／E6）：ホワイトバランスはやや暖かめのニュートラル。床の木とペンダントライトの暖かさは残す。窓の外の空はハイライトを下げ、ロールオフをなだらかにして白飛びさせない。
・料理（9642／9646／E7／E6）：トマトソースとエビの赤、ムール貝の黒を締める。白い皿、白いテーブル、ケーキのクリームのハイライトは飛ばさない。
・全体：コントラストは控えめにし、黒は締めすぎない。Natural / Cleanな仕上げにし、LUTを強くかけたような色やフィルム風のグレインは入れない。

## CapCutで行う作業

1. 0. 中間ファイル（最初に1回だけ。サイネージのEDLと同じ仕様）：全クリップを、元の解像度（横3840×2160／縦2160×3840）・元のfps（60／59.94fps。9646は120fpsのまま）で、FFmpegでSDRの10bit ProRes 422 HQに変換する。縮小やfpsの変更はしない（すると、カット10の1.8倍の切り出しや、カット2を『CapCutだけで作る場合』の340%が拡大になり、カット7の120fpsの0.5倍もコマの重複になる）。FFmpegはフォルダを作らないので、先に mkdir -p exports/work を実行する。コマンド例（1本ずつ）：ffmpeg -i footage/01_撮影素材/IMG_xxxx.MOV -vf "zscale=t=linear:npl=100,format=gbrpf32le,zscale=p=bt709,tonemap=hable:desat=0,zscale=t=bt709:m=bt709:r=tv,format=yuv422p10le" -c:v prores_ks -profile:v 3 -color_range tv -colorspace bt709 -color_primaries bt709 -color_trc bt709 -c:a pcm_s24le exports/work/IMG_xxxx_sdr.mov（縦素材は縦のまま、fpsと音声も元のまま書き出せることを9672と9646で確認済み）。4K・120fpsのProRes HQは1秒あたり約440MB（9646は丸ごとで約15GB）になるので、容量が足りない場合だけ、使う区間の前後1秒を付けて切り出し（-ss と -t を -i の前に置く）、ファイル名に開始秒を入れる（例：IMG_9646_from28.2_sdr.mov。CapCutでの秒＝元の秒−28.2）。CapCutのHDR自動変換は使わない
2. 1. カット2の中間ファイル（9665の縦切り出し）：FFmpegで回転・切り出し・0.5倍まで済ませた、1080×1920・30fps・2.50秒の10bit中間ファイルを作る（切り出し枠を動かす量が細かいので、CapCutのキーフレームより正確）。コマンド：mkdir -p exports/work && ffmpeg -ss 12.15 -t 1.25 -i footage/01_撮影素材/IMG_9665.MOV -an -vf "zscale=t=linear:npl=100,format=gbrpf32le,zscale=p=bt709,tonemap=hable:desat=0,zscale=t=bt709:m=bt709:r=tv,format=gbrp16le,rotate=-2.2*PI/180,crop=1157:2057:'821.7+(442.5-821.7)*t/1.25':'66.5+(95.0-66.5)*t/1.25':exact=1,scale=1080:1920:flags=lanczos,setpts=2*PTS,fps=30,format=yuv422p10le" -c:v prores_ks -profile:v 3 -color_range tv -colorspace bt709 -color_primaries bt709 -color_trc bt709 exports/work/c02_IMG_9665.mov（cropの座標は回転後の画面での左上の値。枠の中心で言うと、元素材の（1400, 1075）→（1020, 1089）。このコマンドで、1080×1920・30fps・2.50秒（75フレーム）・ProRes 422 HQが書き出せ、全フレームで四隅に黒が出ず、水平線が上から約51%で水平なことを確認済み）。CapCutでは、このファイルの0.00〜2.50秒の全部を、速度1.0・回転0°・拡大率100%・位置0で1.50〜4.00に置く。0.5倍・回転・枠の移動はもうかけない（かけると尺が5.0秒になって3カット目以降が2.5秒ずれ、水平線が逆に約2.2°傾く）
3. 2. カット2をCapCutだけで作る場合の目安（中間ファイルを作れないときだけ）：0で作った9665の中間ファイル（3840×2160）を縦のキャンバスに置き、12.15〜13.40秒に切り詰めて速度0.5倍（スムーズスロー＝フレーム補間はオフ）。9665の同期音はミュートする。拡大率は340%（横のクリップを置いたときの初期値を100%として。元素材で1129×2008の枠になる）、反時計回りに2.2°回転。位置のキーフレームはカットの頭と終わりの2つだけにし、補間は直線（イーズなし）。クリップの中心を画面の中心から、頭では右へ約497px・上へ約14px、終わりでは右へ約860px・上へ約42px動かす（1080×1920基準）。黒を出さないための余白は元素材で約46〜64pxある。数値を入れたら、最初と最後のフレームの四隅を400%に拡大して、黒い楔が出ていないか確かめる（CapCutの位置の単位・向き・丸めで数px〜十数pxずれることがあるため）。できれば、FFmpegの中間ファイル（1）から書き出した最初と最後の静止画を上のトラックに半透明で重ね、構図がほぼ重なるか（CapCutの方が約2.5%寄る）を確かめる。水平線が上から約51%で止まって見えること、流れがゆっくり（2.5秒で画面幅の3分の1強）であることも確認する
4. テキスト『海のそばで、少しだけ。』（カット10）：白・Regular・約40px。横は画面の中心（50%）、高さは上から約24%。薄いシャドウ（黒20〜30%、ぼかし約8px）だけを付ける（縁取り・グラデーションなし）。0.4秒のフェード
5. End Card（カット12）：『MAZE WIND』（約48px）のフェードイン → ミニMAP（線3px以上：高知県の輪郭 → 土佐市の点 → MAZE WIND）のMinimal Motion → 所在地とSNSの2行（36px以上・Regular）。すべて画面の中心50%にそろえ、水平線より上に置き、全要素に薄いシャドウを付ける。キーフレームだけで作り、CapCutのテンプレートやアニメーションプリセットは使わない。アカウント名が確定するまで書き出さない
6. Reelsのセーフゾーンのガイド画像を重ねて、文字と主要な被写体が下20%と右端にかからないか確認する（特にカット2の砂州の下の縁と水路、カット5の皿の下の縁、カット7の麺の上端、カット10・12の文字）。カット2は、ガイドを重ねた中間フレームをスマホの実機で見て、水路のエメラルドがUIの間から読めるかを確かめる（承認前の確認と同じ。比較画像は notes_ja）
7. カット2の水路の補強（color_ja）：中間ファイルを上のトラックに複製し、下約22%に上端を大きくぼかした線形マスクをかけ、複製の方だけHSLで青緑（シアン）の輝度を+0.2〜0.3段相当、彩度を+5%前後上げる。色相は動かさない。砂州の下の縁が明るくなっていないかを確認する
8. 回転の目視確認：カット1（2.66°→2.52°、反時計回り、1.10倍）、カット10（0.95°、時計回り）、カット11（0.8°、反時計回り）、カット12（0.7°、時計回り・上端18px下げ）。水平線が動いて見えないか、四隅に黒が出ていないかを見る。カット2は中間ファイルで補正済みなので、CapCutでは回転をかけず、水平線が水平で上から約51%にあるかだけを見る（CapCutだけで作った場合は、2の確認をする）
9. 6.20の『のれんワイプ』：黒い裾がほぼ画面を覆う3.5秒の画から、5.0秒の明るい店内へハードカット。同期音は2フレームだけクロスフェードする
10. 音のJカットとLカット：4.00〜4.80で9658の波音を残してフェードアウト、18.30から9660の波音をLPF 2kHzで入れ始める、22.30でLPFを外す。BGMの音量キーフレームを打ち、29.70〜30.00は波音だけにする
11. BGMの編集：カット位置は動かさず、曲の側を切ってつなぎ、4.00・13.40・24.70に拍を合わせる。13.40〜16.60は持続音を中心にする
12. ラウドネスの確認：CapCutにはLUFSの表示がないので、仮書き出しをFFmpeg（ebur128）で測る。冒頭の波は短時間で−18〜−20 LUFS、本編のBGMは約−16 LUFS、現地音はBGMの6〜8dB下。最後にリミッターで−14 LUFS／−1dBTPに合わせる。ループのつなぎ目（29.70〜30.00と0.00〜0.50）の波音の大きさがそろっているかも聞いて確かめる
13. プレースホルダー（カット8・9）は、仮編集の間だけ『E7（未撮影）』『E6（未撮影）』と書いたグレーの画面を置く。撮影が済むまでは本番の書き出しをしない
14. 最終チェック：1080×1920・30fps・SDRで書き出し、スマホの実機でReelsの表示、End Cardの文字の読みやすさ、カット2の水路の見え方、ループのつなぎ目（30.00 → 0.00の波音）を確認する

前後のつながりも確かめました。カット1（9672、切り出し後で毎秒約21〜26%の右パン）から、同じ向きのカット2（毎秒約14.5%）へ流れが落ち、カット3ののれんの波柄（上から約48〜56%）がカット2の水平線（約51%）の高さで受けます。速度は60fps素材の0.5倍で、下限の範囲内です。カット2に文字はなく、ほかのカットの尺、文字、音も変わっていません。IG15とIG30のカットの振り分けも保たれています。9665はサイネージ（10.2〜12.0秒）と同じクリップですが、区間は重なりません。

直す必要があるのは、主に次の2点です。
・カット2の行に書かれた「0.5倍・2.2°回転・切り出し」は、推奨の作り方（FFmpegで作る中間ファイル）にもう焼き込まれています。行の値どおりにCapCutでもかけると、二重になってしまいます。
・中間ファイルをどう作るか（解像度・fps・トーンマップ・ビット深度）が、IG30には書かれていません。

どちらも書き方の修正で直せます。撮り直しや、カットの組み直しは要りません。
- 条件付きで承認してよいと考えます。カット2（IMG_9665の12.15〜13.40秒、枠を動かしながら縦に切り出し、0.5倍）の技術面の記述は、EDLのFFmpegコマンドどおりに試し書き出しをして、すべて確かめました。見かけの流れは空・海・砂州・水路のどの帯でも毎秒約14%でそろい、0.1秒ごとの動きもなめらかです。水平線は上から50.8%の位置で最後まで止まり、傾きは±0.07°以内でした。四隅に黒は出ず、人影・手すり・消波ブロックも映りません。

物語の順番（海 → 発見 → 入店 → 窓 → 席 → 料理 → 海辺の時間 → 波・空間 → 店名）は崩れていません。カット2の水平線（51%）とのれんの波柄（41〜54%）の高さがそろうので、2→3のつなぎもよく効いています。

弱いところは「発見」の読みやすさです。決め手のエメラルドの水路が画面の80〜93%に入り、ちょうどReelsのキャプションの下に隠れます。さらに、河口そのもの（水路が海へ抜ける地点）は枠の外で、画面の上半分は薄い雲の空です。そのため、スマホで見ると「空・海・白い砂浜」に見えやすく、v2の9670より発見の力が落ちます。

代わりの素材も書き出して比べました。

- 9666の2.40〜3.65秒：枠を動かす方法を使うと流れは毎秒6.5〜14%まで落ち、水路も70〜80%でUIより上に少し出ます。ただし、川が濃紺でエメラルドが出ません。水平線の近くに沖の消波ブロックが残り、斜めに延びる砂州はIG15のHOOKとよく似ます。
- 9671：9670とほぼ同じテイクで、パンも速いです。
