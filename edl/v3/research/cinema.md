# シネアドの映像表現を、屋外サイネージ（無音・16:9・30秒／15秒・ループ）で使える技法に置き換える

対象：Seaside MAZE（南風・まぜ）屋外サイネージ版。描画パイプラインは `tools/v2/common.py` に合わせています（30fps、rgb48le の16bit出力、2.5D視差）。
前提：BRIEF.md §0 の FIXED RULES v2 は変更しません。ここで扱うのは、変更してよい実制作パラメータ（Color、Transition、文字の配置など）だけです。レターボックスとグレインは画の印象を変えるので、EDL承認のときにまとめて確認を取ります。

---

## 0. 要約（先に結論）

1. **「映画らしさ」は質感エフェクトでは決まりません。決め手は間（ま）、余白、動機のある光、少ない言葉、最後にだけ出るロゴの4つです。** グレインやハレーションは仕上げとして薄く入れます。強くすると、テンプレ感（FIXED RULE 4で禁止）と、屋外での見にくさの両方が出ます。
2. **レターボックスは 2.00:1（1920×960、上下60px）を標準にします。** 2.39:1（1920×804、上下138px）は、画面が大きく近くで見る歩行者が多い場合にだけ使います。2.39:1を使う場合は、下の黒帯に「国道56号沿い・高知県土佐市」と右下のロゴを置きます。映画の字幕のような位置になり、読みやすさも上がります。
3. **屋外サイネージでは「完全な黒へのフェード」を使いません。** 昼間は画面が消えたように見え、故障と誤解されます。黒の代わりに深い紺へのディップ（最低輝度8〜12%）を使うか、ディゾルブでつなぎます。
4. **点滅は1秒に3回以下にし、画面の切り替えはゆっくり行います。信号色（鮮やかな赤・黄・緑）と、白ベタの背景は避けます。** これは自治体ガイドラインの共通項です。高知県には映像専用の基準が見つかっていないので、設置前に土佐市・県と警察（交差点付近の場合）への確認が必要です。
5. **「画像のシャドウ」は6通りに解釈し、優先度を付けました。**
   - いちばん効く：窓の光と影が移ろう表現（2Fカフェ）
   - 必須：文字のやわらかい影
   - 少しだけ使う：暗部の持ち上げ
   - 使わない：写真そのものに落とすドロップシャドウ（テンプレ感が出るため）

## 1. 調査で分かったこと（シネアドの特徴と、媒体の前提）

- **シネアドの強み**：暗い映画館の大画面・大音量の中で、観客は逃げられずに一度だけ見ます。媒体資料では「1回の接触でもブランド指標が上がる」「記憶率85%」と書かれています（どちらも媒体側の調査です）。つまり、急いで情報を詰め込む必要がなく、長い間を取れる表現です。
- **地方観光の「しんみり」系シネアドの事例**：具体的にまとまった資料は見つかりませんでした。そこで以下は、日本の旅情系CM・映画の一般的な文法（定点、逆光、ハイキー、短いコピー、縦書きの明朝）から組み立てています。
- **サイネージは条件が逆です**：明るい屋外で、途中から数秒だけ見られ、音がありません。シネアドの文法のうち「間・余白・光・少ない言葉」は使えます。「暗い画・小さい文字・長い暗転・音の演出」は使えません。

### 映画らしい（Cinema）とテレビCMらしい（TV）の違い

| 項目 | TV CM らしさ | Cinema らしさ | このサイネージでの扱い |
|---|---|---|---|
| カット長 | 1〜2秒 | 4〜8秒、定点や一定速度の移動 | **4〜6秒**（BRIEFの3〜5秒の上限寄り） |
| 構図 | 商品を中央に大きく | 余白が多い。水平線を三分割線に置く。窓などで枠の中に枠を作る | 水平線のy座標を全カットで同じにする（RULE 4のマッチカット） |
| 光 | 平らで明るい | 動機のある光（窓・夕陽・逆光）。暗部に情報を残す | 窓の光・反射光を描き足す（§3.6） |
| 文字 | 文字が常に出ている、ゴシック、大きい | 1画面1行、明朝、字間が広い、出ない時間が長い | 短い詩的コピー＋小さな施設情報 |
| ロゴ | 常に出ている／最後に大きく | 最後にだけ、小さく静かに | 右下に小さく常時表示し、ENDで中央に（承認済みの案③） |
| 質感 | シャープでクリーン | 粒子、ハイライトのにじみ、周辺減光 | 薄く入れる（§3.2〜3.5） |
| 色 | 彩度高め | 彩度を抑え、ハイライトをなだらかに収める | §3.7 |
| 物語 | ナレーションで説明する | 画と画の関係（韻、時間の経過、視線）で語る | §5 |
| 終わり方 | 行動を促す一言 | 余韻＋地名 | 「高知県土佐市」で終える |

## 2. 前提となる数値（30fps 基準）

| 項目 | 値 |
|---|---|
| フレームレート | **30p を維持する**。24pで書き出すと、プレーヤーが30/60に変換するときにカクつきが出やすい。映画らしい動きは、180°シャッター相当のモーションブラーで出す |
| 1秒 | 30 frames。30秒版＝900f、15秒版＝450f |
| 1カット | 120〜180f（4〜6秒）。30秒版は6〜7カット、15秒版は3〜4カット |
| 動きの速さ | 2.5Dの寄りは1カットで拡大率+2〜4%。視差の移動量は画面幅の≤1.5%。パンは画面を横切るのに7秒以上（≒9px/f以下） |
| モーションブラー | 3px/f を超える動きでは、サブフレームを3枚（t, t+1/6, t+1/3 frame）重ねて平均する |

## 3. 技法ごとの具体的なパラメータ

### 3.1 レターボックス（16:9の中に映画の画面比を作る）

| 比率 | 映像部分 | 上下の黒帯 | 画面に占める割合 | 評価 |
|---|---|---|---|---|
| 2.39:1 | 1920×804 | 138px ×2 | 74% | 映画らしさは最大。ただし文字と画が小さくなる。歩行者向け・大型画面向け |
| 2.20:1 | 1920×872 | 104px ×2 | 81% | 中間 |
| **2.00:1** | **1920×960** | **60px ×2** | **89%** | **標準として推奨**。映画らしさを出しつつ、面積の損失が少ない |

- 黒帯の高さは偶数px（できれば8の倍数）にします。yuv420のブロック境界に合わせると、帯の縁がにじみません。
- **ループ全体で比率を固定します。** 途中で開いたり閉じたりする演出は、サイネージでは「画面の不具合」に見えます。
- 帯はRGB(0,0,0)のままにし、グレインも乗せません。LEDでは黒の部分がチラつくためです。
- 2.5Dにとっての利点：視差で生じる画面上下端の引き伸ばしを黒帯で隠せるので、縦方向の動き（フロアを上がるカメラ）に余裕ができます。
- 2.39:1を使う場合は、下の帯（138px）に施設情報（40〜48px、オフホワイト）とロゴを置きます。映画の字幕のような見え方になり、画を隠さずに済みます。
- 注意：昼の直射日光の下では、黒帯は反射でグレーに見え、「画面が小さい」と感じられることがあります。実機の写真で確認してください。

### 3.2 フィルムグレイン

- **かけるのは輝度だけにします。** 色の粒子は輝度の0.3倍まで（またはゼロ）。
- 粒の大きさ：1080pでは、正規乱数にガウスぼかし σ=0.6〜0.8px をかけます（見かけ1.0〜1.6px）。
- 強さ（0〜1の表示値の標準偏差）：**0.012〜0.020**（8bitで3〜5段階）。屋外向けの標準は **0.014**。
- 明るさによる重み：`w = 0.35 + 0.65·4Y(1−Y)` で中間調に最も強くかけ、暗部とハイライトでは弱めます。
- 毎フレーム新しい乱数にします（固定すると「汚れ」に見えます）。
- かける範囲：**映像部分だけ**。文字・ロゴ・黒帯にはかけず、文字の読みやすさを優先します。
- 副次的な効果：空や海のグラデーションに出る縞（バンディング）を消すディザとして働きます。グレインの見た目を求めない場合でも、**0.006以上は常に入れることを推奨**します。
- エンコード：H.264 で `-tune grain`、CRF 14〜16（または20〜30Mbps）、`-pix_fmt yuv420p`、BT.709のタグを付けます。サイネージのプレーヤー側で再エンコードされると粒子がブロックノイズに変わるので、実機で必ず確認します。

```python
n = cv2.GaussianBlur(rng.standard_normal((H, W)).astype(np.float32), (0, 0), 0.7)
n /= n.std() + 1e-6
Y = 0.2126*img[...,0] + 0.7152*img[...,1] + 0.0722*img[...,2]   # 表示値 0..1
w = 0.35 + 0.65 * 4*Y*(1-Y)
img += (0.014 * w * n)[..., None] * active_mask[..., None]       # 黒帯・文字は除外
```

### 3.3 ハレーションとブルーム

光が強い部分のまわりが、赤〜桃色ににじむ現象です。作る段階は次の4つです。

1. **しきい値**：リニア光の輝度で **0.78**、ソフトニー0.15。マスクは `m = clip((Y−0.78)/0.15,0,1)^1.5`。
2. **ハレーション（狭い範囲）**：σ=8〜12px、強さ0.08〜0.12で加算。色は **(1.00, 0.50, 0.38)**。
   - 一般的なフィルムの赤橙よりやわらかい桃色にしています。Teal & Orange の禁止に触れないようにするためです。
3. **ブルーム（広い範囲）**：σ=50〜70px、強さ0.03〜0.05。色はニュートラル。
4. **ソフトクリップ**：最後にハイライトを丸め、ピーク白を0.95に収めます。

- 効かせる場所：海面の照り返し、窓の白飛び、逆光の輪郭。
- **海面のきらめきにハレーションをかけると、ちらつきが増えます。** マスクを時間方向に平滑化します（例：`m_t = 0.6·m_t + 0.4·m_{t−1}`）。
- 文字にはかけません（輪郭がにじんで読めなくなるため）。

### 3.4 ゲートウィーブ（フィルムが映写機の中でわずかに揺れる動き）

- 優先度は**低**です（遠くからはまず見えません）。入れる場合の値：
  - 横 0.3px RMS、縦 0.2px RMS、回転 ≤0.01°
  - 揺れの周波数は0.5〜2Hz。サイン波2本と、ローパスをかけた乱数を合成します。
- **揺れは全編で1本の連続した信号にし、カットをまたいでも途切れさせません。** こうしないと、ピクセル単位でそろえた水平線のマッチカット（RULE 4）がずれます。
- 文字・ロゴ・黒帯は揺らしません。
- 小数ピクセルの移動は `cv2.warpAffine(..., INTER_LANCZOS4)` で、1回の再サンプリングにまとめます（視差の変換と合成し、ぼけが重ならないようにします）。

### 3.5 周辺減光（ビネット）

- 楕円形にし、基準は映像部分（黒帯の内側）の半対角線とします。
- 減光は r=0.55 から始め、四隅で **×0.84〜0.88**（−12〜16%）。計算はリニア光の乗算で行います。
- 右下のロゴと白文字は、少し暗くなった隅に乗ることでむしろ読みやすくなります。
- −20%を超えると、屋外では「画面の隅が暗い」不良に見えるので避けます。

### 3.6 「画像のシャドウ」の6つの解釈

| # | 解釈 | 判断 | パラメータ |
|---|---|---|---|
| a | **文字・ロゴのやわらかい影** | **必須**（BRIEF「白・細め・やわらかい影」） | 2層にする。①近い影：オフセット(0,+2px)、σ≈文字サイズ×0.12（64pxの文字なら8px）、不透明度0.45。②広い影：σ≈文字サイズ×0.35、不透明度0.20。色は紺 `#0B1A24`。縁取りは禁止（BRIEF） |
| b | **窓の光と影が移ろう**（窓枠・木漏れ日がテーブルや壁を動く） | **最優先の見せ場**。2Fカフェ。海から光が入ってくることが見え、「海が軸」（RULE 3）にもなる | 窓枠の形のマスクを深度に沿わせて投影する。境界のぼけは近くで4〜6px、遠くで15〜25px。光の当たる部分×(1.06,1.03,0.98)、影の部分×(0.82,0.85,0.90)。移動は0.3〜1.0px/f。**縞模様が画面の1/3を超えないようにする**（ブラインドの縞は「規則的なパターン」の規制に当たる）。`relight.py` を拡張する |
| c | **海の反射光が天井で揺らめく（コースティクス）** | 推奨。音がなくても「海のそば」と分かる | 輝度変調3〜6%、揺らぎ0.2〜0.5Hz、パターンは低周波。速いきらめきにはしない（ちらつき対策） |
| d | **雲の影が海と建物を流れる** | 推奨。外観と空撮の寄りで、時間の経過を表せる | 低周波ノイズで×0.88〜1.0を乗算。流れる速さ20〜40px/s |
| e | **暗部の階調**（黒をつぶす／持ち上げる） | 少しだけ持ち上げる | 黒レベルを0.02〜0.03に（8bitで5〜8）。持ち上げすぎると昼間に白っぽく見えるので、マット調の強いルックは避ける。暗部は青に寄せる（B+2%、Gは変えない＝ティールにしない） |
| f | **ライトリーク**（フィルムの端から光が入るような演出） | 原則使わない。使うならループ内で1回、ENDの前だけ | 立ち上がり30f、保持30f、消え45f。加算のピークは0.06〜0.08。色は桃色寄り。カット点を隠すトランジションとしては使わない（テンプレ感が出るため） |
| — | 写真に枠のドロップシャドウを付ける（ポラロイド風） | **使わない** | スライドショーやテンプレのように見え、RULE 4に反する |

### 3.7 カラーグレーディング（Teal & Orange を使わない海辺の情緒）

狙いは「透明感のあるハイキー、彩度は控えめ、海の青だけは本物」です。日本の旅情系映像に多い、空気の見える色です。数値はすべて表示値（0〜1）です。

1. **ホワイトバランス**：昼の光で中立、5600〜6000K相当。マゼンタ／グリーンの偏りはゼロにそろえる。
2. **色相ごとの彩度**：
   - 全体 ×0.88
   - **青（190〜225°）×1.00**：海、空、仁淀川の「仁淀ブルー」を守る
   - 肌・料理（10〜50°）×0.95
   - 緑（芝生の新居公園）×0.85
   - 赤・黄の高彩度は抑える（信号色に見えないように）
3. **トーンカーブ**：中心0.45のゆるいS字（コントラスト+6%）。ハイライトは0.78から肩で圧縮し、ピーク白は **0.95** に。空を100%に飛ばさないことが、映画らしいロールオフと夜のまぶしさ対策を兼ねます。
4. **色の分け方**：ハイライトは R+1.5%、G+0.5%（朝日の温かさ。オレンジにはしない）。暗部は B+2%、R−1%（紺）。
   - Teal & Orange は「暗部をシアン（G+B）、肌をオレンジ」にする方式です。ここでは暗部を紺（Bだけ）に寄せるので、それと区別できます。
5. **画面の平均輝度（APL）**：1フレームの平均を **0.35〜0.55** に収めます。0.20未満は昼に見えなくなり、0.70超は夜にまぶしくなります。
   - 夕景のEND（22〜30秒）は暗くなりがちなので、露出を持ち上げてAPL≥0.30にします。
6. **写真と動画の統一**（付随ルール）：HDRで撮った動画→SDR BT.709 の変換と、写真の色空間（Display P3→BT.709）を、グレーディングの前にそろえます。

### 3.8 タイポグラフィ

- **書体**：OFLライセンスでGoogle Fontsから入手できます。現在 `assets/fonts` にはNoto Sans JPしかないので、追加が必要です。
  - 詩的なコピー：**Shippori Mincho B1** または **Zen Old Mincho**（Medium〜SemiBold）
  - 施設情報：**BIZ UDP明朝**（UD書体で遠くから読みやすい）、または既存の Noto Sans JP Regular
  - **Lightは使いません。** 明朝の細い横画が、LEDの画素ピッチや縮小表示で消えるためです。横画は**3px以上**を確保します。
- **文字の高さ**：`文字高(px) ≥ 視距離(m) ÷ 150 ÷ 画面の高さ(m) × 1080`。運転者向けは÷150の代わりに÷100で計算します。
  - 例：画面の高さ2m、視距離20mなら、詩的コピー **72〜108px**、施設情報 **40px以上**。
  - 画面の物理サイズは確認中なので、仕様が出たら確定します。
- **字間**：和文 +0.10〜0.18em（`text_layer` の `track` に指定）。英字の大文字 +0.25〜0.35em。行間 1.6〜1.8。
- **文字量**：映画字幕のルール（1行13字以内・最大2行・1秒4字）を参考にします。
  - 運転者向けに **1行7〜12字、1画面1行、表示90f（3秒）以上**。
  - 縦書きの1行（6〜10字、画面の右1/4）は、強く印象を残したい場面で1回だけ使います。
- **出し方**：
  - フェードイン15f（0.5秒、イーズアウト）、表示90〜150f、フェードアウト15f
  - 補助の動きは、+4〜8px浮き上がるか、表示中に字間を0.10→0.13emへ広げる程度
  - 1文字ずつ出す、タイプライター風に出すといった演出は使いません
- **色**：オフホワイト `#F4F1EA`。純白はまぶしく、ガイドラインでも白ベタは避けるよう書かれています。BRIEFの「白」の範囲内です。
- **コピー**：LPの言葉から作ります（事実・呼び方はLPに合わせる）。
  - 場所：「太平洋と仁淀川の交差点。」
  - 締め：「海と、時間と、おいしいもの。」
  - カフェ：「心地よい風が吹く、立ち止まって心と体を休める場所。」（長いので、サイネージでは前半だけにする）
  - フロア名「1F　ローソン＋産直マーケット」などは小さな情報ラベルとして添えます。
- **配置**：映像部分の端から5%内側（タイトルセーフ）に収め、下1/3か中央に置きます。水平線に重ねないようにします（水平線のマッチカットを見せるため）。

### 3.9 ペース配分とトランジション

| 用途 | 長さ（30fps） | 方式 |
|---|---|---|
| 通常のつなぎ | ハードカット／マッチカット | BRIEFの基本 |
| フロア間（場所→1F→2F…） | **ディゾルブ 18〜30f**（0.6〜1.0秒） | リニア光で重ね、`a = smoothstep(t)` で混ぜる |
| 時間の経過（昼→夕） | ディゾルブ 45〜60f | 同上 |
| 黒へのフェード | **使わない** | 代わりに紺 `#0E1B26` へのディップ（下げ12f＋上げ12f、最低輝度8〜12%） |
| ループの継ぎ目（END→冒頭の海） | 45fのディゾルブ、または最終フレーム＝先頭フレーム | 継ぎ目の前後で平均輝度の差を5%以内にする |

- カメラの動きは、等速の台車移動のような**一定速度**が映画らしくなります。イーズは動き全体の最初と最後の10%だけにかけます。弾む・行き過ぎて戻るといった動きは使いません。
- 「どこの5秒を切り取っても伝わる」（BRIEF）ために、各カットの中に海・水平線と、右下のロゴの両方を入れます。

## 4. 音なしで物語を伝える

1. **一本の水平線**：全フロア・全カットで、水平線を同じy座標（例：映像部分の上から38%）に置きます。途中から見ても「同じ海でつながった建物」と分かります（RULE 3・4）。
2. **枠の中の枠**：1Fの入口、2Fの窓、3Fの手すり、タワーの階段のすき間から、それぞれ海を見せます。上の階ほど水平線が遠く広くなり、上へ登っていく感覚を画だけで伝えます。
3. **時間の経過**：光の色と影の長さの変化（§3.6 b・d）で、「立ち寄って、くつろいで、帰る」を表します。
4. **人の気配**：手、カップ、背中、自転車、サーフボードを映し、顔は映しません（ほかの客の顔はNG）。LPの「サイクリスト・サーファー・ドライブ」ともそろいます。
5. **文字をナレーションの代わりにする**：1カットに1行、全体で3〜4行。各行がそれだけで意味が通るようにし、前の行を見ていなくても分かる形にします。
6. **最後は地名で終える**：ENDは「高知県土佐市」「国道56号沿い」で場所を残します。ロゴは静かに出します。

|---|---|---|
| 夜の輝度 | 環境省「光害対策ガイドライン」を引用した自治体の基準では、郊外で400cd/㎡、都市部住宅地で800cd/㎡、繁華街で1,000cd/㎡が上限。福井市は夜間（18〜22時）800〜1,000cd/㎡以下、枚方市は夜間800cd/㎡以下 | 輝度はプレーヤー側の調光（照度センサー・時間帯スケジュール）で決まるので、運用者に確認する。コンテンツ側ではピーク白0.95、APL≤0.55、白ベタ背景なしで支える |
| 深夜の表示 | 福井市は22〜6時の表示を避けるよう求めている | 運用時間を確認する |
| 点滅 | NHK・民放連のガイドラインを、各自治体が引用：**光の点滅は1秒に3回以内、コントラストの強い画面の反転も1秒に3回以内** | フレーム間の平均輝度の変化を自動で検査する（§7） |

## 7. 確認方法（書き出したあとに自動でチェックする項目）

1. **点滅**：フレームごとの平均輝度の差 |ΔY| が0.10を超える回数を、1秒の窓で数えます。3回以上なら不合格です。赤の比率が高いフレームでの変化は、さらに厳しく見ます。
2. **APL**：各フレームの平均輝度が0.20〜0.70の範囲に入っているか。
3. **昼の見え方**：`L' = 0.65·L + 0.30` で外光の反射をまねた画像を作り、それでも文字が読めるか確認します。
4. **遠くからの見え方**：画面の高さと視距離から計算した倍率で縮小し、元の大きさに戻した画で、コピーが読めるか確認します。例：20mから見る場合は1/6に縮小します。
5. **ループの継ぎ目**：最終フレームと先頭フレームの平均輝度の差が5%以内か、水平線のy座標の差が1px以内か。
6. **実機での最終確認**：実機の解像度とプレーヤーで、昼と夜の両方を撮影して確認します。

## 8. まだ確認できていないこと（EDLの前に、お店・運用者に聞く）

- 画面の物理サイズ、表示解像度、LEDか液晶か、画素ピッチ
- 主に見るのは運転者か歩行者か、視距離はどのくらいか
- 調光の仕様と、運用する時間帯
- 土佐市・高知県の屋外広告物の許可条件、道路管理者・警察との協議が要るかどうか
- プレーヤーが受け付ける形式（fps、コーデック、ビットレート、再圧縮されるかどうか）
- レターボックスと明朝体の採用（EDL承認のときに、パラメータの変更としてクライアントに確認する）
